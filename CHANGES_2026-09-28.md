# Changes 2026-09-28

Follow-up to `CHANGES_2026-09-25.md`. This session rebased `development` onto
`origin/main` and fixed three bugs uncovered in the process (two of them
pre-existing in `main` itself, not introduced by the rebase).

## Rebase onto origin/main

`development` was rebased cleanly onto `origin/main`. No true line-level
overlap existed in the handful of shared files, so the rebase itself required
no conflict resolution.

## Bug fixes surfaced during/after the rebase

### 1. `test_all.py`: `ignore_version_diffs` logic was inverted

The test runner's line-comparison helper had `if not ignore_version_diffs and
...: continue`, i.e. it skipped the version-banner line only when the option
was **off**. Fixed to `if ignore_version_diffs and ...: continue`. Verified
with a real pytest run: a previously nominal-failing case
(`Test_solarGS98_base`) now passes, while a genuinely-diverging case still
correctly fails, confirming the fix doesn't mask real differences.

### 2. `src/putstore.f`: FORMAT/WRITE mismatch (crash, present on main itself)

A commit on `main` widened `FORMAT 62` in `putstore.f` to expect 2 integers
+ 4 logicals, matching the convention used in `stitch.f`, but never updated
`putstore.f`'s own `WRITE(ISTOR,62,...)` to supply the new fields. This is a
genuine bug in `origin/main` as-is (confirmed against a pristine checkout),
causing a runtime crash (`Expected INTEGER for item 2 in formatted transfer,
got REAL`) any time the `LSTCH`-off code path is taken in `PUTSTORE` — which
is every current test case, since `LSTCH` defaults to `.FALSE.` and is never
overridden by any test's namelist.

Fixed forward (per direction to apply the new format consistently rather
than revert `FORMAT 62`): the `WRITE` now also supplies `MODEL` (already an
available `PUTSTORE` argument) and the interior/envelope/atmosphere
region-flag triple, mirroring `stitch.f`'s own interior-point call
(`.TRUE.,.FALSE.,.FALSE.`, since `PUTSTORE` only ever writes interior
points).

Because this path is exercised by every test, all 291 `.store` reference
baselines were stale under the old (crashing) code path's assumptions. They
were regenerated via a full test-suite run against the fixed binary
(`test_all.py`'s existing "copy output to reference if missing" behavior).
Note the reference baselines themselves are not tracked in git (no file
under any `standard/` directory is present in `HEAD`) — they are local,
regenerable artifacts, not part of this commit.

### 3. `startmodels/`: file paths standardized to match main's convention

A separate `main` commit (#59) stripped the redundant `testsuite/` path
segment from `{YREC_START}`-relative paths but never relocated the actual
`.last` start-model files that some test cases' `FLAST` entries point at,
leaving those files stranded at their old `startmodels/testsuite/` location.
Relocated the files actually referenced by current namelists to match:

- `startmodels/Test_m1p0feh+0p0GS98_base_TAMS.last`
- `startmodels/Test_m9p0feh+0p0GS98_base_TAMS.last`
- `startmodels/Test_m9p0feh+0p0GS98_yaleeos_TAMS.last`

removed the now-empty `startmodels/testsuite/README.md`. This fixes 5
previously-broken tests that chain off these `TAMS` start models
(`Test_m1p0feh+0p0GS98_base_HeIgnite`, `Test_m9p0feh+0p0GS98_base_TAHB`,
`Test_m9p0feh+0p0GS98_yaleeos_TAHB`, `Test_m9p0feh+0p0GS98_base_TAMS`,
`Test_m9p0feh+0p0GS98_yaleeos_TAMS`).

(Several other `.last` files at this location are not referenced by any
current namelist and were left in place untracked, unchanged from before.)

## Validation

Full 291-case suite, run against the rebased + fixed binary with all
`.store` references regenerated: 289 passed, 2 failed. The 2 failures are
the long-standing, pre-existing chaotic floating-point divergence in
`Test_m9p0feh+0p0GS98_{base,yaleeos}_TAHB`, independently confirmed
unrelated to any change in this branch.
