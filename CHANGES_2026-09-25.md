# Obsolete-option pruning and common-block consolidation (Sept 2026)

This commit is the result of a systematic pass over `src/` to remove obsolete
input-physics options, consolidate related `COMMON` blocks, delete dead code,
and fix a couple of longstanding I/O bugs. Every change below was validated
by rebuilding cleanly and comparing output against the reference test suite
(`test_all.py`, 291 cases spanning `testsuite/` and `examples/`); each pass
reproduced the pre-existing outputs exactly except for a harmless embedded
git-hash version-banner line and two independently-confirmed pre-existing
chaotic floating-point divergences in `Test_m9p0feh+0p0GS98_{base,yaleeos}_TAHB`
that are unrelated to any of these changes.

## Obsolete input-physics options removed

The following namelist options, and every subroutine that existed solely to
support them, were removed. In each case the option's selection logic in
`getopac.f` (or the relevant dispatcher) was collapsed, preserving the
remaining `IF`/`ELSEIF` structure (even down to a single branch) so future
options can still be added the same way, and adding a trap for "no valid
option selected" where one didn't already exist.

- **LMHD** (MHD equation of state) — `meqos.f`, `mhdtbl.f`, `mhdst.f`,
  `mhdst1.f`, `mhdpx.f`, `mhdpx1.f`, `mhdpx2.f`
- **LOPAL92** (OPAL 1992 opacities) — `setllo.f`, `ll4th.f`, `ylloc.f`,
  `yllo2d.f`, `yllo2d2.f`, `yllo3d.f`, `yllo3d2.f`, and (found later, missed
  in the original pass) the now-orphaned `blkdta000.f` `BLOCK DATA` unit that
  only initialized these routines' tables
- **LKUR90** (Kurucz 1990 opacities) — `kurucz.f`, `kurucz2.f`, `setkrz.f`,
  `ykoeff.f`
- **LLAOL89** (LAOL 1989 opacities) — `rdlaol.f`, `sulaol.f`, `gtlaol.f`,
  `gtlaol2.f`
- **LALEX95** (Alexander 1995 low-T opacities) — `alxtbl.f`, `yalo3d.f`,
  `alx8th.f`, `alxztab.f`
- **LMONTE** (Monte Carlo option) — `wrtmonte.f`, plus the ~900-line Monte
  Carlo outer loop in `main.f` collapsed to straight-line code
- **LOPALE / LOPALE01** (older OPAL 1995/2001 equations of state) —
  `eqbound.f`, `esac.f`, `oeqos.f`, `radsub.f`, `readco.f`, `rhoofp.f`,
  `t6rinterp.f`, `eqbound01.f`, `esac01.f`, `oeqos01.f`, `radsub01.f`,
  `readcoeos01.f`, `rhoofp01.f`, `t6rinteos01.f`. **LOPALE06** (the current
  OPAL 2006 EOS) and the shared `IOPALE` unit are untouched.
- **LISO** (isochrone output) — the `LISO`/`IISO`/`FISO` feature was fully
  removed from `parmin.f`, `wrthead.f`, `wrtout.f`, `main.f`
- **IDYN** — a dead unit number removed from the shared `COMMON/LUNUM/`

41 subroutines/functions were deleted in total (verified: 257 → 216 across
the session, with the difference fully explained by these deletions).

## Common-block consolidation

- **`COMMON/CONST/`, `/CONST1/`, `/CONST2/`, `/CONST3/`** → merged into a
  single `COMMON/CONSTANTS/` (29 members), applied atomically across all 98
  files that declared any of the four. `CLSUN`/`CRSUN`, though technically
  namelist-settable, were kept here as tunable physical constants rather than
  folded into the (separately scoped, not-yet-started) namelist-parameter
  consolidation.
- **I/O logical units** — ten blocks that held unit numbers
  (`LUOUT`, `LUNUM`, `ALEX06`, `ACDPTH`, `NEWOPAC`, `LOPAL95`, `ATMOS2`,
  `ALATM03`, `OPALEOS`, `SCV2`) were consolidated into one new
  `COMMON/IOUNITS/`. Four were pure unit-number blocks and moved wholesale;
  the other six mixed unit numbers with unrelated physics/namelist state, so
  only their genuine unit-number members moved — the non-unit members stayed
  in their original (now smaller) blocks. Applied across 74 files.
- **CMIXL** — moved out of `COMMON/CONST3/` and threaded as an explicit
  argument through the 21 subroutines between `main.f` (where it's set from
  the user-input `CMIXLA(NK)` vector) and its consumers (`TPGRAD`, `STARIN`,
  `WRTHEAD`, `WRTLST`, `PUTSTORE`, `WRTMOD`). One exception: `QENV` is
  invoked polymorphically as the `DERIV` callback by the `BSSTEP`/`MMID`
  generic ODE integrator, which always calls it with a fixed, hardcoded
  argument list — adding a normal argument there broke every call reached
  through that path. `QENV` keeps its original signature; `CMIXL` reaches it
  instead via a small dedicated `COMMON/QENVMIX/CMIXLQ`, refreshed by
  `ENVINT` on every entry.
- Three pre-existing common-block member-naming inconsistencies were found
  and two resolved: `DEBHU`'s `XXDY` → `XXDH` (fully unified, 16 files) and
  `SCVEOS`'s `IDTT` → `IDT` where safe (9 of 11 files; `parmin.f`/`starin.f`
  keep `IDTT` because they separately declare an unrelated `IDT` in
  `COMMON/OPTAB/`). `ZRAMP`'s `rscale.f`-only `NK2` was left alone — `rscale.f`
  has its own subroutine argument named `NK`, so unifying it would require
  renaming that argument (and every `CALL RSCALE(...)` site), which is a
  larger, separate change.

## Dead code removed

- `blkdta000.f` (see above), `COMMON/STCH/` (`main.f`), `COMMON/LUNUM/ISCOMP`
  (9 files — `ISCOMP` was its only remaining member, so the block is now
  gone entirely), `ACDPTH`'s `IACAT`/`IJVS`/`IJENT`/`IJDEL` (declared,
  assigned a unit number, `OPEN`/`WRITE` code for all of them already
  commented out — genuinely never used), and `ILSTBN`/`ISTOBN`/`IFSTBN`
  (three more unit numbers assigned in `parmin.f` and never referenced
  anywhere else, not even via a common block).
- `RTAB` (`rtab.f`) was found to be dead — never called anywhere in the
  current codebase — but has **not** been removed; flagging it here for a
  decision.

## I/O bugs fixed

- **Spurious `fort.20`.** `parmin.f` executed `WRITE(ISHORT,NML=PHYSICS)` /
  `WRITE(ISHORT,NML=CONTROL)` *before* the corresponding
  `OPEN(ISHORT,FILE=FSHORT,...)`, so unit 20 was never connected to the
  intended `.short` file when those writes happened — Fortran silently
  auto-created a `fort.20` instead, on every single run, and the namelist
  echo never actually reached the `.short` file. **This has not been fixed** —
  the two `WRITE` statements are commented out for now and flagged inline as
  a live issue (`*** LIVE ISSUE, NOT YET RESOLVED ***`) pending a decision on
  where the echo should go.
- **Spurious `fort.69`.** Two leftover debug `write(69,*)` statements in
  `rotmix.f` (inside the gravitational-settling timestep-restriction block,
  tied to `DT_GS`) wrote to unit 69 without ever opening it. Commented out,
  left in place.
- **`Csound.dat`.** The sound-speed-profile output in `wrtmod.f` (gated on
  `LSOUND`) previously hardcoded both its unit number (500) and filename
  (`'Csound.dat'`), bypassing the managed file/unit system entirely. It is
  now integrated properly: `ISOUND` (=500) was added to `COMMON/IOUNITS/`,
  and `FSOUND` was added to `NAMELIST /CONTROL/` with a default of
  `'Csound.dat'` matching prior behavior (user-overridable like every other
  output filename). The file is opened and rewound unconditionally in
  `parmin.f` at startup — rewound explicitly so a stale file from an earlier
  `LSOUND`-triggering run is never mistaken for fresh output on a run where
  `LSOUND` doesn't happen to fire. Verified against a real solar-calibration
  run: `Csound.dat` is produced correctly (one `Shell#` header, 795 data rows
  matching that model's shell count).

## Known follow-up items (not yet done)

- Move the `PHYSICS`/`CONTROL` namelist echo (currently commented out,
  in `parmin.f`) somewhere it will actually reach the `.short` file.
- Rename `COMMON/OPTAB/`'s `IDT` and/or `RSCALE`'s `NK` argument, to fully
  unify `SCVEOS` and `ZRAMP` respectively.
- Decide whether to delete `RTAB` (`rtab.f`), which is dead code.
- The namelist-user-parameter common-block consolidation (merging the ~64
  blocks that hold namelist-sourced parameters used outside `PARMIN`/`REMAP`,
  excluding the ~75 that are consumed only there to derive other values) has
  been scoped but not started.
- A size-sorted inventory of the remaining ~105 non-namelist common blocks
  was produced to identify further safe consolidation candidates ahead of
  the eventual F90 module conversion, prioritizing small blocks and avoiding
  ones that carry large (`JSON`-dimensioned or bigger) arrays.
